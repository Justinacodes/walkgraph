# FR-005: QR checkpoint generation

**Labels:** labels: fr-005, mus, feature
**Status:** MUS

## User Story

As a mapper, I want to generate QR codes for nodes, so that visitors can start navigation from a scanned checkpoint.

## Proposed Solution

Generate QR codes that deep-link to public navigation with the selected building/node context.

## Implementation Flow

1. Review existing schema, routes, and UI patterns.
2. Create or update feature documentation in `docs/features/`.
3. Implement server/API behavior with Zod validation and authorization checks.
4. Implement UI with server components by default and client components only where interactive.
5. Run `pnpm exec tsc --noEmit` and `python scripts/vibe-verify.py`.

## Technical Approach

- Use Prisma models in `prisma/schema.prisma` as the source of truth.
- Keep API handlers in `app/api/**/route.ts`.
- Keep shared logic in `lib/` or feature service modules.
- Follow `docs/Coding_Guidelines.md`.

## Key Considerations

- Validate all user input.
- Never expose private or service-role credentials to the client.
- Enforce ownership/member authorization for admin operations.
- Prefer clear empty/error states over silent failures.

## Acceptance Criteria

- [ ] QR endpoint returns scannable codes; inactive/missing checkpoints are handled; generated URLs use NEXT_PUBLIC_APP_URL.
- [ ] TypeScript passes with `pnpm exec tsc --noEmit`.
- [ ] Project verification passes with `python scripts/vibe-verify.py`.
