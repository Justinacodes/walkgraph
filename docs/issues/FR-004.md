# FR-004: Shortest-path route testing and public navigation

**Labels:** labels: fr-004, mus, feature
**Status:** MUS

## User Story

As a visitor, I want to search destinations and receive walking directions, so that navigate a published building.

## Proposed Solution

Use the TypeScript Dijkstra routing engine through a validated route API and visitor-facing navigation pages.

## Implementation Flow

1. Review existing schema, routes, and UI patterns.
2. Create or update feature documentation in `docs/features/`.
3. Implement server/API behavior with Zod validation and authorization checks.
4. Implement UI with server components by default and client components only where interactive.
5. Run `pnpm exec tsc --noEmit` and `python scripts/vibe-verify.py`.

## Technical Approach

- Use Prisma models in `prisma/schema.prisma` as the source of truth.
- Keep API handlers in `app/api/**/route.ts`.
- Keep shared logic in `lib/` or feature service modules.
- Follow `docs/Coding_Guidelines.md`.

## Key Considerations

- Validate all user input.
- Never expose private or service-role credentials to the client.
- Enforce ownership/member authorization for admin operations.
- Prefer clear empty/error states over silent failures.

## Acceptance Criteria

- [x] Route API returns shortest path; route tester works; public navigation only exposes published/public buildings; destination search supports names, aliases, and tags; manual start selection and route preview/navigation handle already-there and unreachable states with useful errors.
- [x] TypeScript passes with `pnpm exec tsc --noEmit`.
- [x] Project verification passes with `python scripts/vibe-verify.py`.
